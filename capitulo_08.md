# CAPÍTULO 8. CONCLUSIONES

El desarrollo de Revenfy permitió aplicar diferentes conocimientos relacionados con la arquitectura de software, el desarrollo del backend, el trabajo colaborativo, el control de versiones, la documentación y las buenas prácticas de desarrollo.

A partir del proceso de construcción del proyecto, cada integrante obtuvo diferentes aprendizajes relacionados con las decisiones técnicas y con la forma de trabajar en equipo.

La guía establece que cada integrante debe presentar como mínimo tres conclusiones relacionadas con los aspectos trabajados durante el desarrollo del proyecto.

---

# 8.1 Conclusiones de Anamaria Forigua Murcia

## Conclusión 1. Arquitectura

Trabajar con una arquitectura organizada por capas permite mantener el proyecto estructurado y facilita la comprensión del código. Separar las responsabilidades de cada componente también facilita el mantenimiento y permite identificar con mayor claridad dónde realizar cambios cuando se necesita modificar una funcionalidad.

## Conclusión 2. Desarrollo Backend

Durante el desarrollo del backend se evidenció la importancia de definir desde el inicio las herramientas y la estructura del proyecto. Establecer una organización clara facilita la conexión entre los diferentes componentes y permite desarrollar las funcionalidades de una manera más ordenada.

## Conclusión 3. Trabajo colaborativo

El trabajo colaborativo requiere participar en las diferentes etapas del proyecto, ya que esto permite comprender mejor los conceptos utilizados, conocer el funcionamiento del sistema y entender la dirección que sigue el desarrollo. Participar en diferentes partes del proyecto también permite tener una visión más completa del producto desarrollado.

# 8.2 Conclusiones de Jhon Alex Beltrán Herrera

## Conclusión 1. Buenas Prácticas

Aplicar buenas prácticas desde el inicio del desarrollo permite reducir problemas posteriores. Cuando un proyecto se construye sobre una estructura organizada y con estándares claros, resulta más sencillo incorporar nuevas funcionalidades sin generar conflictos con los componentes que ya existen.

## Conclusión 2. Documentación

La documentación constituye una parte importante del proyecto porque permite conservar el conocimiento relacionado con las decisiones y funcionalidades desarrolladas. Una documentación adecuada facilita que otros integrantes puedan comprender el proyecto sin depender únicamente de la persona que desarrolló determinada parte del código.

## Conclusión 3. Trabajo colaborativo

Un trabajo colaborativo bien organizado permite distribuir el conocimiento entre los integrantes del equipo. De esta manera, las responsabilidades no se concentran en una sola persona y cada integrante puede aportar al desarrollo y comprender diferentes partes del proyecto.

# 8.3 Conclusiones de Luis Mateo Beltrán Repizo

## Conclusión 1. Arquitectura

La organización del frontend mediante carpetas separadas para diferentes responsabilidades permitió comprender que la arquitectura también es importante en la capa de presentación y no solamente en el backend. Separar responsabilidades facilita encontrar y modificar las funciones de una manera más rápida y clara.

## Conclusión 2. Git y GitHub

El uso de Git y GitHub permitió trabajar con mayor seguridad sobre el código, ya que los cambios quedan registrados y es posible consultar versiones anteriores. También se evidenció la importancia de realizar commits claros y mantener un orden adecuado en las ramas para evitar confusiones durante el trabajo colaborativo.

## Conclusión 3. Documentación

Documentar el proyecto durante su construcción permitió comprender mejor las decisiones técnicas tomadas. La documentación no debe considerarse únicamente como un requisito final, sino como una herramienta que ayuda a mantener el conocimiento del proyecto y facilita que este pueda continuar desarrollándose sin depender de una sola persona.

# 8.4 Conclusión General del Equipo

El desarrollo de Revenfy permitió integrar conocimientos relacionados con la arquitectura de software, el desarrollo backend, la documentación y el control de versiones.

La organización del proyecto permitió comprender la importancia de separar responsabilidades y mantener una estructura clara. Asimismo, el desarrollo del backend permitió aplicar herramientas y conceptos relacionados con APIs REST, validación de datos, servicios y conexión con la base de datos.

El trabajo colaborativo permitió distribuir las responsabilidades entre los integrantes y comprender la importancia de mantener una comunicación y organización adecuada durante el desarrollo.

Por otra parte, el uso de Git y GitHub permitió controlar los cambios realizados, trabajar mediante ramas y mantener un historial del proyecto.

Finalmente, la documentación permitió registrar las decisiones tomadas y explicar el funcionamiento de las diferentes partes del sistema, facilitando la comprensión y continuidad del proyecto.
